# Setup — what was installed and how to reproduce it

Everything below was installed **without root network access to Debian/Ubuntu
apt**, using only `pip` (PyPI) and the npm registry, which are the two package
sources this sandbox can reach.

## Machine (measured, not assumed)

| | |
|---|---|
| CPU | 2 vCPU |
| RAM | 3 GB |
| Disk | 21 GB |
| GPU | **none** — no `nvidia-smi`, no CUDA, no PyTorch |
| Network | only `github.com`, `codeload.github.com`, `api.github.com`, `registry.npmjs.org`, `pypi.org`, `files.pythonhosted.org` |
| Blocked | Debian/Ubuntu apt mirrors, `raw.githubusercontent.com`, Azure/Bing speech, Google OAuth endpoints |

That block list is why the film is generated by code instead of by a diffusion
model, and why the voice is eSpeak-NG instead of a cloud TTS.

## Python packages

```bash
pip install --break-system-packages numpy pillow imageio-ffmpeg uharfbuzz freetype-py espeakng-loader
```

| package | why |
|---|---|
| `numpy` | every pixel of every frame is a float32 array |
| `pillow` | Lanczos/Bicubic reconstruction, blur, compositing |
| `imageio-ffmpeg` | ships a static **ffmpeg 7.0.2** binary with libx264 + aac (apt's ffmpeg is unreachable) |
| `uharfbuzz` | **critical**: this Pillow build has **no Raqm**, so Devanagari must be shaped manually or `किताब` renders as broken glyphs |
| `freetype-py` | rasterises the HarfBuzz glyph ids at any size |
| `espeakng-loader` | ships `libespeak-ng.so` + voice data **including Hindi (`hi`)** — a fully offline TTS engine |

## Fonts

Pillow cannot fetch fonts here (`raw.githubusercontent.com` is blocked), so they
came out of npm font packages, which are OFL licensed:

```bash
# @expo-google-fonts/noto-sans-devanagari -> assets/fonts/NotoSansDevanagari-*.ttf
python3 - <<'EOF'
import json, urllib.request, urllib.parse, tarfile, io
pkg = "@expo-google-fonts/noto-sans-devanagari"
meta = json.load(urllib.request.urlopen(
    "https://registry.npmjs.org/%s/latest" % urllib.parse.quote(pkg, safe="@")))
tgz = urllib.request.urlopen(meta["dist"]["tarball"]).read()
with tarfile.open(fileobj=io.BytesIO(tgz)) as tf:
    for want, out in [("400Regular", "Regular"), ("700Bold", "Bold")]:
        m = [x for x in tf.getmembers() if want in x.name and x.name.endswith(".ttf")][0]
        open("assets/fonts/NotoSansDevanagari-%s.ttf" % out, "wb").write(tf.extractfile(m).read())
EOF
```

`assets/fonts/` is committed so a fresh clone can render without network.

## Hindi text: why HarfBuzz

`PIL.features.check("raqm")` returns **False** on this image. Pillow then draws
one glyph per code point, which mangles every conjunct (`ज्ञान`, `किताब`,
`बिल्ला`). `lib/cgilib.py::TextRenderer` therefore does:

```
text ──HarfBuzz utf8→glyph ids + advances/offsets──► FreeType raster per glyph
     ──blit at (pen + x_offset, baseline - y_offset)──► RGBA layer
```

Verified: `ज्ञान` shapes to 3 glyphs (ज्ञ + ा + न with the correct half-form), not 5.

## Hindi voice: why eSpeak-NG

Cloud TTS (Edge/Azure, Google, ElevenLabs) is unreachable, and every neural TTS
weight set lives on HuggingFace, which is also unreachable. eSpeak-NG is a
formant synthesiser, not neural — so `audio.py` hides the buzz with, in order:

* `hi+m3` variant (masculine, ~105 Hz F0 — measured, not guessed: `hi` 103 Hz, `hi+f3` 214 Hz)
* rate 133 wpm, pitch 48, range 60
* high-pass 85 Hz → chest band boost 170–420 Hz → 3 kHz notch (kills the eSpeak
  buzz) → low-pass 7.2 kHz
* double-tracking (two detuned copies at −1.2 % / +1.1 %, 17/29 ms offsets)
* compression (3.2:1 above 0.16) + 0.13 wet room reverb

It reads clearly and carries a story; it will never be mistaken for a human
voice artist. If you want a real narrator, record one and drop the WAVs into
`movie/build/audio/narr_XX.wav` — `audio.py` will use them if `SKIP_TTS=1`.
