## 3. Broken / partial (evidence ke saath)

### 3.1 `NovaVerifiedQueue` executor contract mismatch — **FAILED tasks, silent**
`tasks/task_queue.py` `executor(task)` (1 argument) chalata hai, lekin `tasks/verified_queue.py` `executor(task, arguments)` (2 arguments) expect karta hai.

```
$ python - <<'PY'  … vq.run_next(lambda task: {"success": True, "result": "ok"})
status: FAILED | error: TypeError: <lambda>() takes 1 positional argument but 2 were given
```
Effect: koi bhi purana 1-arg executor verified queue me daala → task silently FAILED, aur error message confusing. `tests/test_verified_queue.py` isi wajah se fail hota hai.
**Fix:** ek hi contract. `run_task` ko `inspect.signature` se adapt karwao, ya `verified.run_next` ko wrapped executor pass karo.

### 3.2 Tool result envelope ka contract break — 2 tests red
`NovaToolRegistry.execute()` ab `{"success": true, "tool": name, "result": {trust, content, security}}` deta hai, par tests/consumers `resp["result"]` ko seedha payload maan rahe hain.

```
$ pytest -q
ERROR tests/test_approval.py           assert {…'trust': 'untrusted'…} == 'Nova'
ERROR tests/test_argument_validation.py assert {…'content': {'result': 'hello'}…} == 'hello'
45 passed, 4 errors
```
**Fix:** `execute()` me `raw=True` / `unwrap()` helper, aur callers + tests ko update.

### 3.3 Tests production state likh rahe hain — contamination
`TaskState()` default path `tasks/state.json` use karta hai (repo ke andar, git-tracked). Test run ne 60 lines add kar diye:

```
$ git diff --stat tasks/state.json
 tasks/state.json | 60 +++++++++++   (my test run; restored afterwards)
```
Repo me pehle se 8 leftover tasks hain (2 PENDING, "Task A"/"Task B" — test data).
**Fix:** `tests/conftest.py` me `TaskState` ko tmp path pe force karo + `tasks/state.json` ko `.gitignore`.

### 3.4 Background autostart toota hua hai — literal `\n`
`automation/install_termux_background.sh` quoted heredoc (`<<'BOOT'`) ke andar `\\n` likha hai, isliye generated boot script me literal `\n` chala jata hai:

```
$ cat -A ~/.termux/boot/nova-start.sh
bash automation/start_fast_lane.sh || true\\nnohup python3 automation/nova_watchdog.py >> … &
```
Shell parse kar leta hai, par word `truennohup`/`true\nnohup` ban jata hai → **watchdog boot pe kabhi start nahi hota** (aur `||` short-circuit hone se watchdog line execute hi nahi hoti).
**Fix:** heredoc me `&&` ya asli newline; phir `bash -n` + `curl /v1/models` test.

### 3.5 Config file load hi nahi hoti
`config/nova.env` me 30+ settings hain (`NOVA_MEMORY_ENABLED`, `NOVA_REQUIRE_APPROVAL_FOR_HIGH_IMPACT`, `NOVA_SELF_HEAL_MAX_RESTARTS` …), par Nova core me koi loader nahi:

```
$ grep -rn "nova.env" --include=*.py .   → (sirf github/local_ai_agent/config.py, wo bhi apna .env)
```
Effect: ye flags sirf tab kaam karte hain jab aapka `jarvis-start` khud `source` karta ho — **UNVERIFIED**, audit se pata chalega.

### 3.6 Dependency drift
`core/tool_bridge.py` → `github/.../tools/web.py` → `requests`. Repo me koi `requirements.txt` nahi:

```
$ python3 -c "import core.tool_bridge"
ModuleNotFoundError: No module named 'requests'
```
`requirements-youtube.txt` me sirf Google libs hain. **Fix:** `requirements-core.txt` + install check in `jarvis-start`/doctor.

### 3.7 Repo hygiene
`git ls-files` → **26 `.pyc`** (cpython-314, phone se), `tasks/state.json`, `logs/qwen.log` tracked. `.gitignore` me sirf youtube entries hain.

## 5. Security review

**Achhi cheezein (preserve karo):** kill switch (file-based, global), audit jsonl with redaction, untrusted-output envelope, deny-list + shell-metachar block, approval gate for `high_impact`, `shutil.which` guard before subprocess, `check_command` length cap.

**Gaps:**

1. **Approval token sirf tool name se bound hai, arguments se nahi** — `approve(token, tool)` `request.tool == tool` check karta hai. Token ke saath **alag arguments** bhejna possible (arg-swap). In-memory hone ki wajah se restart pe pending approvals gayab, aur koi TTL/expiry nahi.
   → *Fix:* approval ko `(tool, sha256(arguments), expiry)` se bind karo; disk pe chhota ledger rakho.
2. **Deny-list approach** — `BLOCKED_PATTERNS` bypass-able hai (e.g. `rm -fr`, `busybox rm -rf`, python one-liner). Saath hi `|`, `>`, `;` block hone se benign commands bhi rukte hain.
   → *Fix:* allowlist + argv validation (already `shell_tool.py` jaisa pattern vendored code me hai).
3. **Risk levels (LOW/MEDIUM/HIGH) nahi hain** — sirf boolean `high_impact`.
4. **Secrets** — ✅ **koi leak nahi mila.** `config/nova.env` me `NOVA_YOUTUBE_CLIENT_SECRET` / `NOVA_YOUTUBE_TOKEN` **paths** hain (values nahi), aur `.gitignore` `youtube/*.json` cover karta hai. Rotation ki zaroorat nahi.
   *Note:* maine pehle ise secret samjha tha; tool ne verify karke false positive pakda — isliye Section 8 ka auditor device pe chalana zaroori hai.

## 8. Device-side audit — abhi ye chalana hai

Repo se phone pe:

```bash
cd /root/OpenJarvis          # ya jahan repo clone hai
git pull                     # tools/jarvis_audit.py aayega
python3 tools/jarvis_audit.py \
  --project /root/OpenJarvis \
  --project "$HOME/Nova" \
  --out "$HOME/jarvis-audit"
```

Ye **read-only** hai: kuch install nahi karta, kuch restart nahi karta, project me kuch likhta nahi.
Jo cheezein check karta hai:

- device: Android version, model, ABI, RAM, storage, battery, termux/proot/root
- Python: version, venv, installed packages + missing (`requests`, `pytest`, `google-genai`, `openai` …)
- binaries: llama-cli/llama-server, ffmpeg, git, curl, termux-api tools, getprop/am/dumpsys
- models: `*.gguf` files + sizes, llama.cpp directories
- ports: `/proc/net/tcp` se listening ports + hints (8080/8081/11434…)
- processes: llama/nova/jarvis/uvicorn/ollama
- project: git branch/HEAD/dirty, file counts, syntax errors (`ast`, bytecode likhe bina), entrypoints
- imports: `core.*`, `security.*`, `tasks.*` ka asli import status
- tools: `build_registry()` se actual registered tool names
- config: `config/nova.env` + `~/.openjarvis/config.toml` ke **key names aur type** (values kabhi nahi)
- state: `tasks/state.json` summary, `logs/audit.jsonl` event counts, kill-switch file
- startup: `jarvis-start` PATH me hai ya nahi, `.termux/boot` scripts, crontab, shell rc references
- network: Gemini/OpenAI/OpenRouter/Anthropic/Groq/GitHub/DDG reachability + latency
- dashboard: local ports pe HTTP kuch answer kar raha hai ya nahi
- tests: `pytest -q` ka summary (agar installed ho)

Output: `~/jarvis-audit/jarvis-audit-<ts>.json` (machine) + `.md` (**ye share karo**).

**Secrets:** sirf key names aur `set/empty/placeholder/path/SECRET-LIKE(len=..)` — values kabhi nahi. MD file paste karne layak hai.
